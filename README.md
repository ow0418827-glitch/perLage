# PerLAGE（感知标签保护生成编辑项目）

本项目由原项目的当前源码迁移而来，保留图像、记忆、检索、智能体、环境、防御和实验编排的分层。原项目保持只读；旧实验结果、生成图片、断点、按日期命名的实验脚本、旧方法说明及原版本管理历史均未带入。

对外只有两个方法：`lucid`（原始像素优化方法）与 `PerLAGE`（感知标签保护生成编辑方法）。感知方法继承原感知优化实现及数值默认值，保留四个必需阶段；方法身份、接口、配置和完成记录已统一改名。

完整流程为：**公开商品图对筛选 → 按方法参数生成 → 校验四阶段或像素步数 → 冻结最终图 → 在同一共享长期记忆池中建立原图及修改图对照 → 全部防御条件检索 → 独立重新编码复算 → 报告**。

## 结构与入口

| 目录或文件 | 职责 |
|---|---|
| `src/vision/pair_selection.py`（公开图对选取模块） | 两种方法共用的第一步，完全离线使用公开数据与本地代理 |
| `src/vision/optimization.py`（方法分派模块） | 仅分派两种现用方法 |
| `src/vision/perlage.py`（感知方法公开接口） | 完整感知生成与身份核对 |
| `src/vision/_perlage/`（感知管线内部包） | 初始化、颜色融合、潜变量细化及证据 |
| `src/vision/_natural/`（通用生成组件包） | 分割、掩码、颜色统计、约束与初始化优化 |
| `src/memory/shared_pool.py`（共享池模块） | 唯一共享基础库、输入合并及评估副本 |
| `src/experiments/pipeline.py`（完整流程入口） | 阶段编排及冻结约束 |
| `src/experiments/shared_evaluation.py`（共享池评估模块） | 固定防御面板、真实复算和报告 |
| `src/agent/`（购物智能体目录）与 `src/environment/`（环境目录） | 购物推理和商城适配，默认不调用 |
| `src/defense/`（防御目录） | 检索后安全核对组件 |
| `src/vendor/`（内置依赖目录） | 真实编码及像素优化引擎，不从旧项目导入运行代码 |
| `src/configs/`（配置目录）、`src/data/`（数据目录）、`src/output/`（输出目录） | 配置、公开及私有输入、独立运行结果 |

## 本机准备与新克隆

本机已建立独立运行环境，原有三个生成模型已复制到本项目模型目录。运行环境与模型不上传仓库；新克隆需要重新准备。软件依赖见 `src/dependencies/requirements.txt`（依赖清单），购物服务端可选依赖另列。

```powershell
.\tools\setup_runtime.ps1
.\.venv\Scripts\python.exe -X utf8 -B tools/prepare_models.py
.\.venv\Scripts\python.exe -X utf8 -B tools/prepare_selection_models.py
.\run_pipeline.ps1 -Stage doctor
```

模型准备工具默认使用中国大陆镜像。若镜像返回不可用或缺少下载元数据，可为模型工具显式添加 `--endpoint https://huggingface.co`（官方模型源地址参数）；感知度量的主干使用视觉库公布的官方原始权重并校验摘要。训练与评估阶段始终只加载本地权重，不自动下载或切换模型。

## 准备新实验输入

已有原始商城商品数据时，可使用 [公开数据选图入口](docs/PUBLIC_SELECTION.md)。当前第二版只按粗类型兼容、灰度全局外形门槛及去重判断合格，再使用固定种子均匀抽样。阈值须绑定真实公开开发集校准；每目标初始预算32张，不按综合最高分取图。候选阶段只使用一个冻结视觉模型，选中后才准备主体与印刷区标注、实际视觉核对和最终发布。完整公式见[选图协议](docs/PAIR_SELECTION.md)。

图对确定后，正式输入放在 `src/data/public/groups/<协议运行版本>/<组名>/`（公开分组目录）；已有无版本目录的冻结图对保持可读。每组顶层继续使用 `source.jpg`（原商品图）和 `target.jpg`（目标商品图），保留实际格式及字节。该目录的 `pipeline.json`（本组完整流程配置）让两种方法直接读取两张图。商品身份、摘要、抽样和选中图对标注证据均绑定保存。

1. 使用公开选图入口，或将 `src/data/public/catalog.example.json`（公开商品清单示例）复制为实际清单，提供公开图、名称和来源。先完成公开开发集校准，再筛选和抽样；只给选中的图对补齐主体和印刷区标注。缺少实际核对时，生成入口保留抽样记录并等待，不加载生成模型。没有文字也须显式核对并保留空列表。
2. 准备一个共享池。原实验中的私有记忆及结果没有自动导入，避免把旧结果搬进新项目。共享池工具可从用户明确提供的多份基础记忆合并并复制原图，保留完整历史，不运行购物。
3. 将 `src/configs/pipeline.example.json`（完整流程配置示例）复制为本地配置并调整公开清单及运行目录。两种方法共同使用评估配置中的唯一共享池路径，没有按组记忆映射。

共享池导入命令如下。真实购买输入必须有完成证据；模拟图库须选择对应类型，不能伪装为已购买记忆。基础共享池禁止导入旧对抗替换。

```powershell
.\.venv\Scripts\python.exe -X utf8 -B tools/build_shared_memory.py --input <输入文件路径> --kind purchase_memory
```

这里 `purchase_memory`（真实购买记忆）与 `simulated_gallery`（模拟图库）是两种明确的数据来源标签。合并已标注的混合来源输入时，可使用 `preserve`（保留逐条来源），但每条输入必须已有明确标签。实际共享池默认位于本项目私有数据目录，不受版本管理。

## 执行与比较

```powershell
.\run_pipeline.ps1 -Stage all -Method lucid -Config src/configs/pipeline.local.json
.\run_pipeline.ps1 -Stage all -Method PerLAGE -Config src/configs/pipeline.local.json
```

`all`（完整检索流程）在同一运行根目录复用已冻结的公开选取结果，再分别生成两种方法的图片；不按任何私有结果重新选商品。两种图片分别存放于该运行目录的方法子目录。运行目录、公开输入、筛选配置或代码发生变化时，须另建运行目录。

可用阶段包括 `select`（公开筛选）、`generate`（生成并冻结）、`evaluate`（共享池检索与复算）、`verify`（独立重新编码复算）、`report`（生成报告）和 `doctor`（运行依赖检查）。单独执行评估阶段必须已有绑定公开选取的完整冻结图片。

默认评估器使用独立留出的公开大模型编码器，避开生成时的三个小型代理。评估器配置示例单独存放；部署时可在私有数据目录提供评估器实际配置。此设置用于检验跨模型迁移，不代表已完成真实平台效果验证。

## 模糊查询图待实现

生成并冻结图片后，流程写出 `QUERY_IMAGE_REQUEST.json`（正式查询图片要求）。模糊图片的生成目前明确未实现；未提供实际独立图片时，完整入口返回状态码二并写入等待查询图状态，不读取共享库进行正式检索，也不回退到目标商品原图。

后续按该要求单独生成图片，并在私有数据目录提供 `query_image.json`（查询图片清单），记录实际图片路径、内容摘要、公开目标标识，以及“无明确商品名称、无品牌”的实际人工核对结果。核对字段是审核声明，程序不把它当作自动视觉证明。文字默认采用二十个不含具体商品名或品牌的泛指请求。

## 评估及后续购物

默认固定二十六种设置，汇总为十四行，保留三档扩散各五个种子。报告同时给出进入前三和前五。所有共享池图片施加同样防御，查询图保持不变；池内跨品类条目不会按当前商品过滤。图片与真实商品名的检索权重各半，历史、操作、观察及价格不参与检索键。

结果复算使用新建编码器，重新计算全部查询及图库向量、名次与分数，不将“只重加一遍命中数”称为独立复算。检索命中不能写成购物成功。

下游购物能力保留于独立适配模块和 `tools/run_shopping.py`（购物评估工具）。默认停止标记持续有效；后续真实测试须另行明确启用本次运行、准备商城和本地接口配置。下游仍复用同一共享池和同一模糊图文查询，仅接受具备真实购买历史的记忆作为购买示例。迁移及验证没有调用商城或外部生成模型。
