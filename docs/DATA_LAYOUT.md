# 数据目录的迁移差异与当前用途

公子，迁移时不仅复制了方法代码，也重整了数据入口。原项目把提示模板、旧文字指令和九组文字映射放在数据根目录；当前项目将公开选图与训练素材、评估记忆与正式查询分开。这有助于执行黑盒数据边界，但目录分层并不要求改变购物附加指导。此前省略旧中性模板并另写比较图片的指导，属于额外的实验设置变化，不能把它当作迁移的必然步骤。

本说明依据本地目录及实际调用核对。原项目保持只读；当前文件数量和缓存大小不是原亚马逊商品全集的大小。

## 原数据根目录中的各项

## 当前目录分别放什么

- `src/data/indication_prompt_template_neutral.json`：已恢复的中性附加指导。文件内容与用户指定的旧文件一致。
- `src/data/public/`：公开商品索引、下载图片缓存、公开开发校准集、选图记录及实际发布的分组图对。两种方法都从同一份冻结图对读取原商品图和目标图。
- `src/data/public/groups/02_chair/`、`09_toothbrush/`：目前实验实际使用的两组旧协议图对，便于查看的名字为原商品图、目标图以及感知方法成图。新简化协议的预检没有覆盖它们。
- `src/data/private/`：共享长期记忆、评估副本所需输入，以及两组正式模糊请求和参考图。这里的“私有”表示训练和公开选图不能访问的评估边界，不表示加密机制。
- `src/output/`：实验计划、冻结记录、索引副本、逐次轨迹、运行日志、结果和本地候选方案备份。它们没有被当作版本库中的固定训练数据。

当前共享记忆沿用用户随后授权复制的旧一百条全局库，再以两组新商品的真实本地商城购买记录替换对应两条，其余九十八条保留。它与训练竞争池不是同一概念，也没有恢复按组单独记忆库。

公开数据目录中的大量文件主要是下载缓存、校准素材、特征缓存和元数据。看到文件数增加，不代表已经对这些商品完成生成、检索或购物测试。

## 商品全集与仍然存在的外部路径

原商品全集没有被删除，也没有整体塞进当前数据根目录。本次目录清点只读取路径、文件数量及大小，不重新扫描商品全文。

需明确的是，当前独立商城适配仍只读使用相邻旧项目的商品磁盘索引 `lage/src/output/nine_group_catalog_full`，并使用相邻 `MINJA-main/rap/webshop` 的商城实现。相关路径集中在 `src/experiments/shared_shopping.py`。方法代码已内置到当前项目，但这个大型商品数据与商城测试依赖仍是外部路径，不能据新目录布局声称整个测试环境已经完全自包含。

## 为什么保留独立检索复核

独立复核重新创建编码器，重新计算图片和名称向量，核对源图片替换后是否仍使用旧索引、完整共享库是否一致，以及名次和汇总是否准确。它与正式生成和购物模型调用分离。

本次将两组批量入口的初次编码、独立复核和购物检索默认计算设备改为显卡，没有删除复核，也不在显卡失败时静默回退。复核记录保存实际设备。文件读取、摘要和排序仍属于普通主机工作，不能把使用显卡描述为整个程序完全不使用处理器。

## 简化选图流程是否已经进入实验

尚未使用其新图对进行方法生成或正式评估。已有预检为：理发椅检查三十二个候选、零个通过；牙刷检查三十二个候选、三个通过，并得到一个暂选源商品。由于整批不满足发布条件，没有覆盖旧分组图对，生成次数为零，正式检索和购物次数也为零。

两版改色测试与本轮中性提示复测都沿用原有冻结图对，不是简化选图规则的独立效果验证。
